Superbuild commands
===================

Run from this directory (UnrealFolder/ProjectMobius).


## The short version, any platform

    python superbuild.py

Builds and installs Assimp, HDF5 and (Win64 only) the MobiusIfcBridge DLL into the exact layouts
UnrealBuildTool reads, then verifies every file it will look for. Requires Python 3.8+ and
CMake 3.21+; use python3 instead of python on macOS/Linux.

It reconfigures automatically when the build tree cannot be reused -- generated on another
machine, or for a different Visual Studio, MSVC toolset or CMake version -- and says which of
those it was. You should not need to delete _superbuild by hand.

Useful switches:

    python superbuild.py --clean          # discard the build tree first
    python superbuild.py --rebuild        # also discard the installed dependencies
    python superbuild.py --skip-ifc       # skip the long IFC++ pass
    python superbuild.py --force-ifc      # rebuild MobiusIfcBridge after editing its .cpp/.h
    python superbuild.py --config Debug
    python superbuild.py --generator "Visual Studio 17 2022" --toolset 14.38.33130
    python superbuild.py --help


## Plain CMake, any platform

Fully supported; the Python script is a convenience layer, not a requirement.

    cmake --fresh -S . -B _superbuild -DCMAKE_BUILD_TYPE=Release
    cmake --build _superbuild --config Release --parallel

`--fresh` (CMake 3.24+) is the "clear the old build files" half: it discards the existing cache and
reconfigures. That is the fix for a _superbuild directory copied in from another machine, or one
generated by a different compiler. Drop `--fresh` for an ordinary incremental build.

Note there is deliberately no -G. CMake picks the newest installed Visual Studio itself, and the
platform default for VS 2019+ generators is already the host architecture. Naming a generator is
what broke this project: the docs used to hardcode "Visual Studio 17 2022", which on a machine with
a different Visual Studio fails with

    CMake Error: Generator "Visual Studio 17 2022" could not find any instance of Visual Studio.

-DCMAKE_BUILD_TYPE is ignored by multi-config generators (Visual Studio, Xcode) and --config is
ignored by single-config ones (Ninja, Makefiles), so the pair above is correct on every platform.

What you give up versus superbuild.py: the MSVC toolset is not pinned to 14.38.33130 (the one
UE 5.5 builds with), and the toolset can only be chosen at configure time. To pin it by hand,
note that the version alone is NOT enough -- name the platform toolset too, or the VS 2026
generator rejects it:

    cmake --fresh -S . -B _superbuild -T v143,version=14.38.33130


## Run the staging checks on their own

    ctest --test-dir _superbuild -C Release --output-on-failure

Each check names one file, and they are the files UnrealBuildTool probes. A failure here is the
same failure you would otherwise hit twenty minutes into an Unreal build.


## Optional: drive the Unreal build from ctest

    cmake -S . -B _superbuild ^
      -DSUPERBUILD_ENABLE_UE_GENBUILD=ON ^
      -DUE_BUILD_EXE="D:/UE_Engines/UE_5.5/Engine/Build/BatchFiles/Build.bat" ^
      -DUE_BUILD_ARGS="ProjectMobiusEditor Win64 Development -Project=ProjectMobius.uproject -WaitMutex -architecture=x64"

Every other option is documented at the top of CMakeLists.txt.
